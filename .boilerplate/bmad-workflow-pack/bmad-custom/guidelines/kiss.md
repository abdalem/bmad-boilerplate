# KISS Engineering Guideline

Apply KISS by default.

- Prefer the smallest clear change that satisfies the acceptance criteria.
- Do not introduce broad refactors, new abstractions, dependency changes, architecture rewrites, or unrelated cleanup unless the work item explicitly requires it or the user approves it after trade-offs are presented.
- Keep implementation scoped to the current work item and its acceptance criteria.
- If useful cleanup is discovered, record it as follow-up work instead of doing it inside the current task.
- When choosing between a simple local change and a more general abstraction, choose the local change unless there is clear repeated pressure in the current scope.
